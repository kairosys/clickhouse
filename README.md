# ClickHouse

Analytical database serving as the backend for **[Langfuse](https://langfuse.com) v3** self-hosted observability. Stores all Langfuse analytical data (traces, observations, scores, prompts). Runs as a Kubernetes `StatefulSet` with fixed DNS identity and local persistent storage; exposes HTTP/REST on **8123** (used by the rest of the stack) and native TCP on **9000**. Single-node deployment (`replicas: 1`), Atomic database engine.

This directory contains configuration + runtime data only (no source code or test suite here).

> `data/` mirrors a running server's files — `metadata/*.sql`, `preprocessed_configs/`, runtime markers. These are regenerated by the live server; do not edit to change schema, use SQL instead. The `.gitignore` excludes nothing that would safely protect committed secrets.

---

## Overview
ClickHouse is deployed as a Kubernetes `StatefulSet` named `clickhouse` with an attached headless Service of the same name (namespace `furseal`). Every object hard-codes `furseal`, so DNS names resolve like `<pod>.clickhouse.furseal.svc.cluster.local`. The instance exposes one database (`CLICKHOUSE_DB=langfuse`) and listens on two ports consumed by Langfuse's HTTP/REST API (8123) and its native client migration protocol (9000). Storage is local to the worker node via a hostPath mount so data survives pod restarts.

## Architecture & Specifications
### Pod / StatefulSet layout
- `kind: Service` — headless (`clusterIP: None`), selects pods labeled `app=clickhouse`, ports mapped 8123→`http`, 9000→`native`. Defined in the same file as the StatefulSet (single YAML, two documents separated by `---`).
- `kind: StatefulSet` — name `clickhouse`, replica count **1**, strategy type `RollingUpdate`, service name pinned via `spec.serviceName: "clickhouse"`. Container is `name: clickhouse`; image **`clickhouse/clickhouse-server:latest`** (unpinned tag).

### Storage configuration
**No PVC/PV object ships in this repo.** Persistent storage uses a node-local hostPath directory mounted into the container at `/var/lib/clickhouse`:

```yaml
volumeMounts:
  - name: clickhouse-data
    mountPath: /var/lib/clickhouse   # engine data root (config <path>/var/lib/clickhouse/)
volumes:
  - name: clickhouse-data
    hostPath:
      path: /mnt/workspaces/clickhouse/data   # node-resolved; NOT mapped from this workspace's ./data/ here
      type: DirectoryOrCreate
```

- The runtime data tree (`metadata/`, `preprocessed_configs/`, `status`, `uuid`) is mirrored under `./data/` in *this* repository for offline inspection only. Do not edit those files to alter schema — the live server owns them and will overwrite changes on restart.
- `/mnt/workspaces/clickhouse/data` must be created/presented **on each target node** before applying; otherwise ClickHouse starts with an empty data directory. Symlinks from this repo's `data/` are not honored by hostPath resolution (that is node local).

### Exposed ports
| Port  | Name      | Protocol / usage                                                                 |
|--------|-----------|---------------------------------------------------------------------------------|
| `8123` | `http`    | HTTP/REST API (primary interface used by Langfuse)                              |
| `9000` | `native`  | Native TCP protocol — native client and server-to-server / migration traffic    |

### Compatibility settings
No feature-gate env var is declared. This instance effectively runs single-node, equivalent to **cluster disabled** (`CLICKHOUSE_CLUSTER_ENABLED=false`): one shard, no ZooKeeper. Observed runtime config (from `data/preprocessed_configs/config.xml`) sets auth default type to `sha256_password` but also enables insecure flags — `allow_plaintext_password=1`, `allow_no_password=1`, `allow_implicit_no_password=1`. If you expose 8123/9000 beyond a trusted network, front them with TLS/reverse proxy and tighten access before production use.

## Configuration & Environment Variables
Declared across `k8s/clickhouse-secret.yaml` (surfaced into the Pod via `envFrom`) and an explicit override in the container env block of `k8s/clickhouse-statefulset.yaml`. Because credentials are checked in as plaintext under Git, assume compromised and **rotate before any push** — nothing in `.gitignore` excludes them by content. Namespace is hard-coded to `furseal`; change explicitly on each object if deploying elsewhere.

| Variable               | Source                | Default value / effect              | Notes |
|-----------------------|----------------------|-------------------------------------|---------------------------------------------------------------|
| `CLICKHOUSE_USER`      | Secret (Pod `envFrom`)  | `clickhouse`                        | Auth user the rest of the Langfuse stack connects as; stored plaintext in `k8s/clickhouse-secret.yaml`. Rotate before pushing. |
| `CLICKHOUSE_PASSWORD`   | Secret (`stringData`)    | *(redacted — rotate before push)* | Password for the user above, pulled from the same secret. Treat as compromised at deploy time and scrub/rotate before any publication; nothing in `.gitignore` hides it from git history. | |
| `CLICKHOUSE_DB`        | Pod env override       | `langfuse`                          | Database a Langfuse client connects to by default (override of the server's compiled-in `default`); schema DDL for this DB appears under `data/metadata/default.sql`. |

## Deployment Guide (namespace: furseal)
Apply in dependency order so later objects can resolve their references. All manifests hard-code namespace `furseal`; it must exist before applying the Secret/Service/StatefulSet, and `/mnt/workspaces/clickhouse/data` should be present on each target node — otherwise ClickHouse starts empty.

```bash
# 1) Namespace (hard-coded in every manifest below)
kubectl get ns   furseal || kubectl create ns      furseal

# 2) Secret first -> auth must exist before Pod envFrom resolves, else a restart may be required to pick it up
kubectl -n furseal apply     f k8s/clickhouse-secret.yaml

# 3) Headless Service + StatefulSet (single YAML under --- separator creates both objects)
kubectl -n furseal apply   -f k8s/clickhouse-statefulset.yaml && \
 kubectl -ns               wait    --for=jsonpath='{.items[0].ready}' pod -l app=clickhouse && \
 kubectl get                svc,sts,po -n furseal

# (optional) Port-forward the headless Service to localhost for local HTTP diagnostics:
kubectl -n furseal port-forward svc/clickhouse 8123 &>/dev/null & sleep 1; echo "ready"          \
```

> Path quirk: this macOS-side working tree is at `/Users/kevin/Workspaces/clickhouse/data`; the pod instead mounts node-local hostPath `/mnt/workspaces/clickhouse/data`. Do not create a symlink here expecting it to map onto the cluster — paths resolve on the *node running the Pod*, not your filesystem.

## Health Checks & Diagnostics
```bash
# 1) Object + endpoint layout (single headless Service + single Replica StatefulSet)
kubectl -n furseal get svc,sts,po -l app=clickhouse
kubectl    port-forward   svc/clickhouse 8123:8123

# 2) HTTP liveness/readiness ping — "1" means healthy on the REST interface
curl http://localhost:8123/ping

# 3) Auth smoke via default user, against CLICKHOUSE_DB=langfuse (see Configuration table):
PW=$(kubectl -ns furseal get secret clickhouse-secret -ojsonpath='{.stringData.CLICKHOUSE_PASSWORD}') && \
curl --user "clickhouse:$PW" 'http://localhost:8123/?query=SELECT+version()'

# 4) Schema verification against the live server (DDL source-of-truth mirrored at data/metadata/*.sql, read-only):
kubectl -n furseal exec   ist ts/clickhouse -- clickhouse-client \
      "SHOW DATABASES; SHOW CREATE TABLE langfuse.traces LIMIT 1;"          # native TCP port 9000 aware

# 5) Disk/inspection view the server itself reports (data dir footprint + per-disk free):
kubectl -n furseal exec    sts/clickhouse -- clickhouse-client \
 "SELECT hostName(), path, formatReadableSize(sum(size_bytes)) AS bytes
   FROM system.parts GROUP BY hostName(), path;"

# 6) In-pod filesystem inspection of the data root (does NOT replace a SQL read):
kubectl -n furseal exec sts/clickhouse -- du        /var/lib/clickhouse | tail -1
```
